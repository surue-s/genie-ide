2. EXTERNAL APIS & SERVICES
================================================================================

PISTON API (Code Execution Engine)
├─ Base URL: https://emkc.org/api/v2/piston
├─ Purpose: Execute code in multiple programming languages safely
├─ Authentication: None (public API)
├─ Rate Limiting: None (public service)
└─ Supported Languages:
    - JavaScript (18.15.0)
    - TypeScript (5.0.3)
    - Python (3.10.0)
    - Java (15.0.2)
    - C (10.2.0)
    - C++ (10.2.0)
    - Go (1.16.2)
    - Rust (1.68.2)
    - PHP (8.2.3)

PISTON API ENDPOINTS:
1. POST /execute
   └─ Executes code and returns output
   ├─ Request Body:
   │  ├─ language: string (language identifier)
   │  ├─ version: string (language version)
   │  └─ files: Array<{content: string}>
   └─ Response:
      ├─ run: {output: string, stderr: string}
      └─ compile: {output: string, stderr: string}

│  └─ String matching for file name references
│

   └─ Returns: 0 (none), 1 (weak), 3 (strong)

6. DATA FLOW ARCHITECTURE
================================================================================

USER INPUT → EVENT HANDLER → STATE UPDATE → RE-RENDER → DISPLAY

Example: Code Execution Flow
1. User clicks "Run Code" button or presses Ctrl+Enter
2. Output.runCode() is called
3. Gets source code from editorRef.current.getValue()
4. Calls executeCode(language, sourceCode) from api.js
5. axios POST to https://emkc.org/api/v2/piston
6. Piston API executes code in container
7. Response with output/stderr
8. Component updates state: setOutput(), setIsError()
9. UI re-renders with new output

Example: File Switch Flow
1. User clicks file in FolderManager or HexFileNavigator
2. onSelect callback triggered with fileId
3. setCurrentDocumentId(fileId) called
4. currentDocument changes via useMemo
5. CodeEditor re-renders with new document.text
6. CodeMirror editor displays new code

Example: Dependency Visualization
1. HexFileNavigator mounts
2. analyzeFileDependencies(documents) runs
3. Parses each file's code for imports
4. Returns dependency graph: {fileId: {imports, importedBy}}
5. For each file pair, getDependencyStrength() calculated
6. ConnectionLine SVG rendered with appropriate color/style
7. Dependency indicators shown below hexagons

7. FILE FORMAT SPECIFICATIONS
================================================================================

DOCUMENT OBJECT:
{
  id: string (UUID),                    // Unique identifier
  language: string,                     // 'javascript', 'python', etc.
  text: string,                         // Source code content
  title: string,                        // Filename with extension
  version: number,                      // Incremented on each change
  updatedAt: number                     // Timestamp in milliseconds
}

PISTON API RESPONSE:
{
  run: {
    output: string,                     // stdout
    stderr: string,                     // stderr
    exitCode: number
  },
  compile: {
    output: string,
    stderr: string
  }
}

DEPENDENCY ANALYSIS RESULT:
{
  [fileId]: {
    imports: string[],                  // Names of imported files
    importedBy: string[],               // IDs of files importing this
    mentions: string[]                  // IDs of files mentioning this
  }
}

SHORTCUT DEFINITION:
{
  key: string,                          // Key code
  ctrl: boolean,                        // Requires Ctrl
  shift: boolean,                       // Requires Shift
  description: string                   // Human-readable text
}

11. PERFORMANCE CONSIDERATIONS
================================================================================

OPTIMIZATION STRATEGIES:
├─ Lazy import for heavy components
├─ Memoized dependency analysis
├─ Event delegation for hex navigator
├─ Ref-based DOM access (no re-renders)
├─ SVG for dependency lines (lightweight)
└─ Debounced resize handler for output

POTENTIAL BOTTLENECKS:
├─ Large file count → Dependency analysis O(n²)
├─ Complex regex parsing → Use memoization
├─ Many hexagons → Virtualize if >100 files
├─ Large code files → CodeMirror handles well up to ~1MB
└─ API latency → Network dependent (Piston)

MEMORY MANAGEMENT:
├─ Documents stored in state
├─ Editor ref cleanup on unmount
├─ Event listeners removed in cleanup
└─ No global variables used

15. TROUBLESHOOTING GUIDE
================================================================================

CODE WON'T EXECUTE:
1. Check network connection
2. Verify Piston API is online
3. Ensure language is supported
4. Check for syntax errors
5. Try simpler code first

HEX VIEW NOT SHOWING CONNECTIONS:
1. Ensure files have import statements
2. File names must match import paths
3. Check language is supported
4. Verify syntax is correct

KEYBOARD SHORTCUTS NOT WORKING:
1. Check focus is on window, not input
2. Some shortcuts may be OS-reserved
3. CodeMirror editor may override shortcuts
4. Check for modifier key conflicts

PERFORMANCE ISSUES:
1. Limit files to <100 for dependency analysis
2. Keep individual files <1MB
3. Close unused files
4. Restart application
5. Check system resources
